# omp-config

English | [简体中文](README.zh-CN.md)

- **Harness configuration**
  - `agent/config.yml` — Does: the machine harness config applied to `~/.omp/agent`: model-role labels (`modelTags`), subagent model bindings (`task.agentModelOverrides`), worktree isolation (`task.isolation`), the compaction method order, the `bashInterceptor` patterns that reroute shell commands to built-in tools, `edit.mode: hashline`, `retry.fallbackChains.web` and the other session settings. When: read by OMP on every start after the updater applies it. Example: `task.agentModelOverrides` binds `task:mid` to `commandcode/deepseek/deepseek-v4.1-flash:high`, `compaction.methodOrder` is `remote → soft → snapcompact → handoff → shake` with `asyncEnabled: false`, and an interceptor pattern sends `cat`/`head`/`tail` calls to `read` with the message "Use the `read` tool instead of cat/head/tail/less/more."
  - Model-role tags — Does: names the `/model` picker entries the extensions' helper roles bind to. When: resolved whenever an extension asks for its `@<extension>` role. Example: `modelTags.input-polish.name: Input polish`, `modelTags.task-completion-judge.name: Task completion judge`.
  - `agent/config-light.yml` — Does: light-mode override that replaces the `extensions` list with `extensions-last/system-prompt-replace`, drops the eight interactive/judge extensions via `disabledExtensions`, sets `task.eager: "default"` and turns `bashInterceptor` off. When: loaded instead of `config.yml` when `omp-light` launches OMP. Example: `disabledExtensions: extension-module:turn-judge, extension-module:tool-policy-nag, extension-module:watchdog-agent`.
  - `agent/omp-light.ts` — Does: a Bun launcher that spawns `omp` with `OMOMP_MODE=light` and `config-light.yml`, passing the machine `config.yml`'s own extension paths (non-`extensions-last` entries like `~/.claude`) back through `-e` so light mode keeps them. When: run by the user as the `omp-light` command installed beside `omp`. Example: child spawned with `env: { ...process.env, OMOMP_MODE: "light" }`.
- **Prompt layer files**
  - `agent/SYSTEM_TEMPLATE.md` — Does: the Handlebars base system-prompt template OMP renders (`{{personality}}`, `{{#if renderMermaid}}`, `{{#ifAny skills.length alwaysApplyRules.length rules.length}}` slots), edited down so tool-specific prose lives elsewhere. When: rendered into every session's base system prompt. Example: `{{#if personality}}# Personality\n{{personality}}{{/if}}`.
  - `agent/PERSONALITY.md` — Does: the personality-slot text injected through `{{personality}}`. When: rendered into the base prompt of every session. Example: `Evidence-first terse engineer: every sentence fact, decision, or risk.`
  - `agent/APPEND_SYSTEM.md` / `APPEND_SYSTEM_LIGHT.md` — Does: the unconditional appendix OMP appends after the template (user-instruction precedence, final-reply style, document-context rules); the light-mode variant is a placeholder. When: appended to the system prompt of every session (full and light respectively). Example: `# User instructions take precedence — Every rule in this appendix is a default for when the user has said nothing else`.
- **tool-topics (`agent/extensions/tool-topics/`)**
  - Description rewrite — Does: replaces each covered built-in tool's rendered description with its `SURFACE-*.md` surface plus an index of its topics, found by tool name inside OMP's rendered prompt layouts. When: at every `before_agent_start`, main and sub sessions, when the session has `read`; returned as the result's `systemPrompt`. Example: `SURFACE-read.md` replaces the `read` description and the prompt then lists `help://read/json` as a topic.
  - Unified `help://` handler — Does: augments OMP's native `help` scheme on the internal-URL router to serve `TOPIC-*.md`, shared plugin topics, and native `docTopics()` together: `help://` lists tools, `help://<tool>` lists its topics, `help://<tool>/<topic>` returns one body. When: resolved whenever the model reads a `help://` URL. Example: `read help://edit/hashline-moves` returns that topic's markdown.
  - Topic injection — Does: `TOPIC-*.md` frontmatter `inject:` rules `{id, tool, parameter, pattern}` deliver the topic body once per context as trusted `additionalContext` under marker `omp-config/tool-topic-injection` when a tool result's named string argument matches the pattern. When: after a `tool_result`, including failed results. Example: `TOPIC-read-json.md` injects when a `read` call's `path` ends in `.json`, so the model gets the jq-query instructions right after the call.
- **system-prompt-replace (`agent/extensions-last/system-prompt-replace/`)**
  - Wording edits — Does: `REPLACE-SYSTEM-*.yml` rules rewrite passages of the rendered system prompt (`literal` verbatim, `regex` with `$1` substitution, conditioned by `target`/`cwd`/`model`/`provider`/`mode`/`delegation`/`exclude.*`), returned as the edited `systemPrompt` itself. When: re-read and re-matched at every `before_agent_start`; loaded as the last `extensions` entry of `config.yml` so it runs after every other extension. Example: `REPLACE-SYSTEM-default.yml` targets `subagents` to blank out "No TODO tracking, no progress updates." and adjusts eval guidance under `delegation: eager`.
- **append-system-model (`agent/extensions/append-system-model/`)**
  - Conditional prompt fragments — Does: every applying `APPEND-SYSTEM-*.md` (frontmatter keys `enabled`, `target`, `cwd`, `model`, `provider`, `mode`, `delegation`, `exclude.*`; discovered beside the extension and from cwd up to the git root including each `.omp/`) is appended as one hidden delta message with source `omp-config/append-system-model`. When: re-read and matched at every `before_agent_start` and `tool_result` in main and subagent sessions. Example: `APPEND-SYSTEM-decision-support.md` with `target: main`, `exclude.model: ^claude-opus-5-5$` injects "For a consequential decision, consult both `discuss:steady` and `discuss:divergent`".
- **repo-rules (`agent/extensions/repo-rules/`)**
  - Context files — Does: delivers `AGENTS.md` / `CLAUDE.md` from cwd up to the repo root (`config.yml` disables the native `agents-md`/`claude-md` providers that would render them into the prompt under absolute paths) as messages, paths written relative to the repo root so worktrees get identical bytes. When: at every `before_agent_start` and after every `tool_result`, only when the delta changed. Example: this repo's root `AGENTS.md` reaches the model as part of the `omp-config/repo-rules` delta.
  - Unscoped and unlisted rule files — Does: scans `.claude/rules`, `.agents/rules`, `.pi/rules` and `~/.claude/rules` for rule files OMP's native discovery skips (no `alwaysApply`, no `description`, unknown directory) and delivers their bodies, or lists frontmatter files by `name`/`description`/path. When: same delta points as above. Example: a `.pi/rules/foo.md` without frontmatter is delivered verbatim.
  - Path-scoped rules — Does: a rule whose frontmatter has `paths:` globs (project, user, plugin and extension-root `rules/` all included) is delivered as `tool_result` `additionalContext` the first time a `read`/`write`/`edit` (or a plain `cat`/`head`/`tail` `bash` call) touches a matching file, once per context; native rules with `paths` keep their prompt presence but are re-scoped. When: after the tool call that touches a matching path. Example: this repo's `.claude/rules/judge-prompts.md` arrives when `agent/extensions/turn-judge/**` or an `INTENT-*.md` file is touched.
- **Subagent roster (`agent/agents/`)**
  - `task:high` — Does: the only worker tier that can delegate further (`spawns: task:mid, task:low, task:free, task:high, discuss:steady, discuss:divergent, mentor:default`); its description forbids dispatch without explicit user permission. When: spawned by the `task` tool; bound by `task.agentModelOverrides` to `anthropic/claude-opus-5-5:high`. Example: `task-high.md` description: "FORBIDDEN without explicit user permission".
  - `task:mid` — Does: the default worker tier for bounded slices outside design and core work; `completionJudge: true` and `splitCheck: true` frontmatter opt it into the judge extensions. When: spawned by the `task` tool; bound to `commandcode/deepseek/deepseek-v4.1-flash:high`. Example: `spawns: mentor:default` only, so it executes its slice itself.
  - `task:low` — Does: routine-tier worker on DeepSeek V4.1 Flash and the validator for free-tier results. When: spawned by the `task` tool; bound to `commandcode/deepseek/deepseek-v4.1-flash:high`. Example: `task-low.md` description names it "the validator for free-tier work".
  - `task:free` — Does: low-trust probe tier for leads and candidates whose errors are harmless. When: spawned by the `task` tool; bound to `commandcode/deepseek/deepseek-v4.1-flash:low`. Example: `task-free.md` frontmatter `completionJudge: true, splitCheck: true`.
  - `discuss:divergent` / `discuss:steady` — Does: read-only discussion partners (`tools: read, grep, glob`), expansive vs. conservative stance, for arguing plans and decisions through. When: spawned through `task` or messaged during a task; bound to `anthropic/claude-opus-5-5:medium` and `commandcode/deepseek/deepseek-v4.1-flash:high`. Example: `discuss-steady` "stress-tests a plan, design, or diagnosis against the actual code and evidence".
  - `mentor:default` — Does: tool-less mentor consulted before long investigations and debriefed before delivery; stays reachable by `write agent://<id>`. When: spawned per task; bound to `commandcode/deepseek/deepseek-v4.1-flash:high`. Example: frontmatter `tools: []`; the shipped `PROMPT-INJECT-user-goal.md` feeds it the user's verbatim requests.
  - `reviewer` — Does: code-review specialist kept bound to the `@slow` role. When: spawned by `task` with `agent: "reviewer"`. Example: `task.agentModelOverrides.reviewer: "@slow"`.
  - Disabled bundled agents — Does: `task.disabledAgents` hides OMP's bundled `task`, `scout`, `sonic` and `security-reviewer` so spawns resolve to this roster. When: at every `task` call's preflight. Example: `disabledAgents: [task, scout, sonic, security-reviewer]`.
  - `agents/README.txt` (+ `README.zh-CN.txt`) — Does: repo-shipped authoring notes recording observed subagent-definition pitfalls (dead `task` tool without `spawns`, `disabledAgents` blocking allowlisted names, why this file is `.txt`). When: read by whoever edits these definitions; never shipped to the prompt. Example: item 1 documents the refusal `Cannot spawn 'mentor:default'. Allowed: none (spawns disabled for this agent)`.
- **Dispatch gates**
  - task-split-check — Does: judges `task` call items with yes/no questions before dispatch: `split` (main session; items whose agent declares `splitCheck: true` — does the item cover more than one topic) and `report-limit` (every session; every `task:*`/unset-agent item — does the dispatch cap the report length); any flag blocks the whole call with the reasons, and prompts are remembered per process by content hash. When: at `tool_call` on `task`, model from the `@task-split-check` role then `default`, under a 25 s deadline. Example: re-dispatching the same `split`-flagged prompt unchanged passes as a `repeat`, while a capped report must instead write long output to a file.
  - isolation-nudge — Does: blocks a `task` call that would leave two or more write-capable agents sharing the session's working directory without `isolated: true`, once per unseen prompt text; an agent is write-capable unless its definition limits it to OMP's read-only tools (an omitted `agent`, `task:*`, `dispatch-owner` and session-defined agents count, `discuss:*`, `mentor:default` and `scout` do not), and `isolated: false` is a deliberate choice that never triggers. It stays silent while the `task` tool offers no `isolated` parameter (isolation off, plan mode). When: at `tool_call`, counting shared writers of earlier calls in the same turn (cleared at `turn_start`) and running shared writer jobs recorded at `tool_result`. Example: the block reason lists `` `task:mid #1` (dispatched earlier in this message) `` and tells the model to "Re-dispatch the writers with `isolated: true`".
  - task-completion-judge — Does: inside a subagent whose definition declares `completionJudge: true`, a fast model compares the assignment, the subagent's recent calls and its `yield` payload, and blocks the first terminal `yield` judged `NOT_DONE` (or a `DONE` yield while its `omp-todo-ng:read` projection still has open items), each at most once per session. When: at `tool_call` on the yield tool in judged subagent sessions, model from `@task-completion-judge` then `default` under a 25 s deadline. Example: the verdict is "the reply's leading first-line token: `DONE`, `NOT_DONE` or `NOT DONE`".
  - user-prompt-inject — Does: renders `PROMPT-INJECT-*.md` templates (`{{user_prompt[i]}}`, `{{user_prompt[a:e]}}`, `{{ask_answers}}` from the root session's prompts and `ask` answers) into a request-only developer message placed first for the targeted subagents. When: on every `context` event (each model call, including IRC wakes) in a targeted subagent. Example: `PROMPT-INJECT-user-goal.md` targets `mentor:default, discuss:steady, discuss:divergent` with "These are the human user's own requests to the root session, verbatim and in order".
- **Deletion boundary**
  - delete-guard guard lane — Does: parses every `bash` call in the pi-shell dialect and every `eval` cell with its own py/js readers, and blocks deletion commands (`rm`, `unlink`, `rmdir`, `shred`, `find -delete`, PowerShell `Remove-Item`, cmd `del`/`rd`, interpreter calls like `shutil.rmtree`/`fs.rmSync`) and non-literal command text (expansion-built names, nested shells from stdin, `eval`/`trap` bodies) before anything runs — failing closed on unparseable input. When: at `tool_call` on `bash` and `eval`; independent of `tools.approvalMode` and `bashInterceptor`. Example: `bash rm -rf build/` is refused and the reason points to the `delete` tool.
  - `delete` tool — Does: the only sanctioned deletion path: literal paths only (no `~`, env or globs), default `mode: "trash"` moves to the system trash, `mode: "permanent"` needs interactive confirmation and refuses root/home/session-cwd and their ancestors. When: registered on supported platforms; called by the model instead of shell deletion. Example: `delete({paths: ["dist/"]})` reports "delete (trash): all 1 done".
- **tool-policy-nag (`agent/extensions/tool-policy-nag/`)**
  - pty lane — Does: refuses non-PTY `bash` calls and `eval` cells that start passthrough, terminal or open-ended commands before any process starts, in main and sub sessions, with a `help://bash/terminal` pointer (`pty: true` calls pass). When: at `tool_call`, when `tool-policy-nag.pty.enabled` is on and the session has `write_stdin`. Example: `bash ssh host` or `bash htop` without `pty: true` is refused with `help://bash/terminal`.
  - form lane (`heuristic`) — Does: deterministically counts operations a built-in tool covers (`shell-parser`/`shell-command`/`shell-programs` classify each program; a traced run's `details.trace` supplies the commands that actually ran) and reminds with `form.prompt` once hits exceed `form.afterHits`, at most `form.maxNags` per context; while this detector runs it also overrides `bashInterceptor.enabled = false` on the live settings. When: judged at `tool_result` in the main session; reminder rides `additionalContext`. Example: repeated `cat`/`ls`/`grep` shell calls produce a reminder to use `read`/`glob`/`grep`.
  - intent lane (`jev`) — Does: asks the JUDGE backend one `choice` question per watched call — what the call accomplishes and which built-in tool owns that intent — using the `INTENT-*.md` spec's options, and reminds naming intent and required tool when the verdict passes `intent.threshold`. When: the question starts at `tool_call`, the reminder lands at `tool_result`; main session. Example: `INTENT-policy.md` option `read` has `title: 读文件内容`, `` tool: "`read`" ``, covering `cat package.json` and `tar -xO -f b.tar x`.
  - risk lane — Does: reminds about calls whose outcome the agent cannot read off the result: a traced step that failed silently (non-zero status nothing tested, no output), or text-judged calls exceeding `risk.minCommands`/`risk.minChars`/`risk.minPrograms`. When: at `tool_result`, main session, when `tool-policy-nag.risk.enabled`. Example: a chained command whose middle step exits non-zero with no output gets a silent-failure reminder.
  - `tool-policy-nag.*` plugin settings — Does: all lane behavior is configured through `omp-config` plugin settings read at every watched call (project `.omp/plugin-overrides.json` wins over machine values). When: on each watched call; editable via `/settings → Plugins → omp-config` or `omp plugin config`. Example: keys `tool-policy-nag.detector`, `tool-policy-nag.form.afterHits`, `tool-policy-nag.intent.threshold`, `tool-policy-nag.risk.minPrograms`, `tool-policy-nag.pty.enabled`.
- **Session-move and restart tools**
  - `wt` — Does: queues the human's own `/wt` through `executeBuiltinSlashCommand` to create a git worktree (branch `wt/<yyyymmdd-hhmmss>` by default) and move the session into it after the turn ends; an already-worktree session gets a report plus a `confirm` hash instead. When: armed on `agent_end`, executed once the session is idle; TUI main session only, refused in vibe mode. Example: `wt({branch: "fix-x"})` returns a queued acknowledgement and the outcome arrives as the next message.
  - `wt_remove` — Does: two-call removal of the session's worktree: the first call dry-runs and returns what would be deleted, blockers (running jobs, subagents inside) and a `confirm` fingerprint of the worktree state; the second call with a matching fingerprint queues `/move` back to the main checkout plus a forced `git worktree remove` that keeps the branch. When: same queue/arm timing as `wt`; TUI main only. Example: `wt_remove({})` then `wt_remove({confirm: "<hash>"})`.
  - `harness_restart` — Does: queues the human's `/restart` (same launch flags, session resumed from disk), records the request as a durable `custom` session entry, and after the restart delivers an attributed restart-completed message with the `reason`. When: queued at the call, armed on `agent_end`, run once idle; TUI main only. Example: `harness_restart({reason: "load new extension"})`.
- **Reviewer and judge monitors**
  - watchdog-agent — Does: `WATCHDOG-<label>.md` files (extension dir plus repo walk) declare per-target reviewers with `target`/`cwd`/`watchModel`/`watchProvider` scope filters, a chat reviewer (`model:`) or JUDGE options (`option.<label>`), cadence `every: 30`, `scope: full|window`, `delivery: aside|steer|nextTurn|followUp`, `inject: system|user|none` (`none` = observer that runs a background task with its tools and never messages the watched session); each watched action (tool call or text reply of a matching message) advances a counter that triggers the review mid-run or at `agent_end`, and the cursor persists as a session entry. When: `session_start/switch/branch/tree/compact/shutdown`, `tool_result`, `input`, `before_agent_start`, `message_end`, `agent_end`; main and sub. Example: a file with `target: task:mid`, `every: 30`, `option.halt: …` reviews that tier's sessions every 30 actions.
  - `/watchdog` command — Does: lists discovered watchdogs, toggles them per session or globally (`on|off <name> [session|global]` rewrites the file's `enabled:`), and `add`/`edit`/`rm` manage spec files. When: on `/watchdog` in the TUI. Example: `usage: /watchdog [list] | on|off <name> [session|global] | add <requirement> | edit <name> [change] | rm <name>`.
  - turn-judge — Does: `TURN-JUDGE-<label>.md` files (same discovery, plus `skipTools`, `inject: system|user`, `maxBytes` state budget) put `question.<id>` yes/no questions to `openJudge` about the judged turn's `{ 时间线, 本轮回复 }` state, and send the file's `prompt:` when a `when.<name>` probability expression holds. When: at `message_end` for a turn that ended `stopReason: "stop"` with nonempty text, in files' `target`/`cwd`/`model`/`provider` scope; main and sub. Example: shipped `TURN-JUDGE-gpt-talk-only.md` (`target: main`, `model: (^|/)[Gg][Pp][Tt]`, `skipTools: wt, harness_restart`) sends its Chinese resume-work prompt when `says_remaining >= 0.6 & announces_future >= 0.3` holds.
  - lang-nag — Does: judges the last paragraph outside fenced code blocks of the main session's terminal reply (last `agent_end` text, `stopReason: "stop"`, first 200 code points) against the configured language and prepends the configured instruction (e.g. `说中文`) to the next user message on a mismatch; a pending verdict is aborted when the next message is sent. When: detection starts at `agent_end`, injection at `input`; main session only; settings `lang-nag.language`/`lang-nag.instruction`. Example: `lang-nag.language: 中文` + `lang-nag.instruction: 说中文`.
- **Conditional model handling**
  - model-compaction — Does: the `rules` list of `model-compaction.json` (`provider`/`model` regexes + `thresholdTokens`, discovered beside the extension and cwd→git-root including `.omp/`) write the matched models' native `compaction.modelThresholds` entries (`"provider/id": "f<threshold>"`) into the runtime settings layer, never a config file; a rule that would change a model's context-window tier or does not fit below its largest window is refused. When: main-session `session_start`, `session_switch` and `before_agent_start`; restored on `session_shutdown`. Example: a rule `{ "provider": "^anthropic$", "model": "opus", "thresholdTokens": 150000 }`.
  - argon-long-output — Does: for models with `api: google-gemini-cli` and id `^gemini-4-argon`, fills the stream-watchdog timeouts OMP would otherwise cap at 300 s (compat layer, options/settings/env still win) and injects `ARGON_PROMPT.md` as a delta telling the model to keep every `write`/`edit` payload and final reply under 8,000 characters. When: model patching on `context` (before every model call), full sweep at `session_start`/`before_agent_start`/`session.compacting`; prompt delta at `before_agent_start`/`tool_result`. Example: `ARGON_PROMPT.md` — "No single `write` content, no single `edit` body, and no single final reply text exceeds 8,000 characters."
  - ast-top-level — Does: writes `ast_grep` and `ast_edit` into the host's process-wide `TOOL_COMMAND_KEEP_TOP_LEVEL` table so they stay function tools instead of bash tool commands, then re-applies the session's active tool set so the partition takes effect. When: at extension load and on `session_start`. Example: `TOOL_COMMAND_KEEP_TOP_LEVEL["ast_grep"] = true` keeps `ast_grep` callable directly while `ast_edit`'s preview is still applied with the `resolve` command.
- **TUI and language**
  - omomp-lang — Does: exports the `omomp-lang.language` plugin setting as `process.env.OMOMP_LANG` once per process so every omomp plugin and extension resolves its person-facing text (`_shared/i18n.ts`, `omomp-shared/i18n.ts`); an `OMOMP_LANG` already in the launch environment wins. When: at module load, before the extension factories of the same batch; reports an invalid setting at the first main `session_start`. Example: `omomp-lang.language: zh` makes `tr("Subagent Usage", "子代理用量")` return the Chinese label.
  - input-polish — Does: binds a chord (`input-polish.key`: `ctrl+enter` or `alt+enter`) so pressing it instead of Enter starts a `@input-polish`-role model rewrite of the input draft in an overlay; Enter accepts the polished draft into the editor and submits, Esc/Ctrl+C aborts; drafts starting with `/`, `!` or `$` pass through. When: raw terminal-input listener in the main TUI session (`session_start`/`session_switch` attach); instruction from `input-polish.instruction`. Example: chord `ctrl+enter`, overlay shows the streaming rewrite while the editor keeps the original draft.
  - child-memory-warning — Does: a process-shared monitor warns the UI and the agent when an owned descendant OS child process's macOS phys_footprint exceeds `child-memory-warning.thresholdGiB` (2 s scans via libproc, PID+birth ownership retained after reparenting; no kills). When: started at main `session_start`, refreshed on `session_switch`, cleared at `session_shutdown`; setting read every scan. Example: `child-memory-warning.thresholdGiB` plugin setting, a positive number in GiB.
- **Usage and release surface**
  - `subagent_usage` tool — Does: estimates how many more dispatches each available subagent can make before its first bound model's provider quota runs out, using per-dispatch averages and USD-per-quota constants calibrated from this machine's last 21 days of session transcripts (`<agentDir>/cache/subagent-usage/`, `calibration.json`); prints pools grouped by provider where counts inside a pool are alternatives. When: callable once consent is granted via `/subagent-usage on`; `defaultInactive` until `session_start`/`session_switch` activates it. Example: output groups agents into `POOL`s that share one quota.
  - `/subagent-usage` command — Does: `status|on|off|recalibrate|reset` — the human's consent switch (`subagent-usage.enabled`, machine scope only) plus recalibration and data deletion; without `on` no transcripts are read and the tool stays inactive. When: on `/subagent-usage`. Example: `/subagent-usage on` "consents to reading this machine's sessions and usage history".
  - omomp-changelog — Does: discovers installed omomp members (packages with top-level `omomp.changelog` in `package.json`, plus `omp-config` itself via `_shared/package.json`), diffs each member's `CHANGELOG.md` against `<agentDir>/omomp-changelog/seen.json` and shows the new sections as a widget above the editor (`startup.changelogMode` `summary`/`expanded`/`hidden`); `/omomp-changelog [full|last [N]]` prints release days without touching the marker. When: widget at main `session_start` with a UI, dismissed by the first user message; command on `/omomp-changelog`. Example: `/omomp-changelog` defaults to the latest 3 release days grouped by date.
  - omp-config-autoupdate — Does: applies the omp-config repo to `~/.omp/agent`: at `session_start` from GitHub `release` when `omp-config-autoupdate.enabled` is on, or on demand; runs `agent/extensions/omp-config-autoupdate/omp-config-update.ts` which does preflight, three-way customization merge, plugin install/upgrade per `install-plugins.sh`, retirements, `_shared` plugin linking and `omomp.*` settings migration; `exclude` entries are never written; a run that changed something shows a 5 s widget. When: automatically per start (opt-in) or via the command; conflicts follow `omp-config-autoupdate.conflicts` (`notify` or `agent`, which starts the adaptation in the session). Example: `/omp-config-autoupdate [status|on|off|run|adapt|conflicts notify|agent]`.
- **Plugin list and audit**
  - `install-plugins.sh` — Does: the one-way declaration of omomp plugins the updater and onboarding install: `omp install` for each entry of `plugins=(…)`, with `omp-remote-build` commented out as the optional one. When: run manually by the user, or read by the updater's apply. Example: entries `https://github.com/oh-my-omp/omp-actual-terminal#release`, `omp-todo-ng#release`, `pi-pretty-codeblocks`, `omp-thinking-translator#release`, `omp-playbooks#release`, `omp-ask-ng#release`, `omp-peers#release`, `omp-sessions#release`, `omp-subagent-ng#release`, plus `https://github.com/mouriya-s-lab/pi-bansos`.
  - `plugin-audit.sh` — Does: diffs the plugin names `install-plugins.sh` ever required (from commit `BASE=5974c4fa…` to HEAD) against `omp plugin list --json` and classifies them: `[安装]` missing, `[卸载候选]` removed-but-still-installed, `[保留]` self-installed or optional, `[已同步]`. When: run manually inside the repo, and by `/update-omp check`. Example: sections `[安装] 脚本要求但本机缺失 -> 跑 ./install-plugins.sh` and `[卸载候选] … -> 询问用户后 omp plugin uninstall <name>`.
- **Test sandbox (`sandbox/`)**
